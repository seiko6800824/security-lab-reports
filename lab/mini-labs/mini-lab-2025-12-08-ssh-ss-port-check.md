# Mini Lab 2025-12-08 – sshdログとポート確認

## 1. 今日やったこと

- `journalctl -u ssh -n 30 --no-pager` で最近の SSH ログを確認。
- `ss -tuna | grep ':22'` で SSH(22番ポート) の LISTEN 状態を確認。
- `ss -luna 'sport = :53'` で DNS(53番ポート) の待ち受け状態を確認。

## 2. 観察したログのポイント（要約）

- `Server listening on 0.0.0.0 port 22` という行があり、
  SSHサーバ(sshd)が **全てのIPv4アドレスで 22番ポートをLISTEN** していると分かった。
- `Accepted publickey for seiko from 192.168.XX.1 port 64001 ssh2`
  などの行から、
  クライアント(Windows側)のIPは 192.168.XX.1 で、
  **クライアント側ポート(64001/59585など)は接続のたびに変わる一時ポート**
  であることを再確認した。
- サーバ側のポート22は固定で、VS Code Remote-SSH などからの接続を
  いつでも受けられるよう **待機(LISTEN)** している。

## 3. `ss` コマンドで確認したこと

- `ss -tuna | grep ':22'` の結果に `0.0.0.0:22 LISTEN` があり、
  journalctl のログと同じ状態を別のコマンドから確認できた。
- `ss -luna 'sport = :53'` の結果で、
  `127.0.0.53:53` や `127.0.0.54:53` のようなアドレスが複数見えたが、
  これは **127.0.0.0/8 のループバック範囲の中で DNS 用に使い分けているだけ**
  であり、ポート競合ではないと理解した。
- `127.0.0.53%lo:53` の `%lo` は、ループバックインターフェース名
  （lo）を示すタグのようなものであり、「文字化け」ではない。

## 4. 学び・気づき

- **journalctl と ss を組み合わせることで、ログのメッセージと実際のポート状態が頭の中でつながった。**
- サーバ側の22番ポートは固定でLISTENし続け、
  クライアント側のポートだけが毎回変わる、という
  「クライアント／サーバの役割分担」がイメージしやすくなった。
- ループバックアドレス(127.0.0.x) と DNSポート(53) の組み合わせは、
  自宅ラボの内部で完結する情報であり、適切にマスキングすれば
  公開しても安全であることを確認した。

## 5. 環境メモ

- 環境: VirtualBox 上の Ubuntu Server 24.04 LTS
- 接続方法: Windows から VS Code Remote-SSH で接続
- 公開用に IPアドレス・ホスト名は一部マスキング済み。
