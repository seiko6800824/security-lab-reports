# ufw と http.server で 8080 ポートを公開・遮断する実験

## 1. 目的

- Ubuntu 上で `python3 -m http.server` を使い、TCP 8080 番ポートで簡単な HTTP サーバを起動する。
- `ufw`（Ubuntu のホスト型ファイアウォール）で、
  - 外部（Windows ホスト）から **アクセスできない状態**
  - ルールを追加して **アクセスできる状態**
  を切り替え、挙動の違いを確認する。
- HTTP アクセスログから、自分のアクセス（200 / 404）の意味を読み取る練習をする。

## 2. 実験環境

- ホストOS：Windows 11
- ゲストOS：Ubuntu Server 24.04 LTS（VirtualBox）
- ネットワーク：Host-Only
  - Windows 側 IP : `192.168.56.1`
  - Ubuntu 側 IP : `192.168.56.101`
- SSH：Windows → Ubuntu へ OpenSSH で接続
- ログ採取：`script` コマンドで `~/lab/logs/YYYY-MM-DD_HH-MM/net_components.log` に保存

#採取ログ
192.168.56.1 - - [05/Dec/2025 23:04:38] "GET / HTTP/1.1" 200 -
192.168.56.1 - - [05/Dec/2025 23:04:38] "GET /favicon.ico HTTP/1.1" 404 -

## 3. 手順

### 3-1. ufw の有効化と状態確認

```bash
# 状態確認（この時点では inactive）
sudo ufw status verbose

# SSH 用ルール追加
sudo ufw allow OpenSSH

# ufw 有効化
sudo ufw enable

# 再度状態確認
sudo ufw status verbose
Status: active
Logging: on (low)
Default: deny (incoming), allow (outgoing), disabled (routed)

To                         Action      From
--                         ------      ----
80,443/tcp (Apache Full)   ALLOW IN    Anywhere
22/tcp (OpenSSH)           ALLOW IN    Anywhere
...
Python の簡易 HTTP サーバを 8080 番で起動
# ホームディレクトリで実行
python3 -m http.server 8080 &
Serving HTTP on 0.0.0.0 port 8080 (http://0.0.0.0:8080/) ...
#Ubuntu 自身からアクセスしてみる：
curl http://localhost:8080
#結果：

ブラウザ → 接続タイムアウト

PowerShell → 接続できません のようなエラー
#理由：8080はデフォルト設定であっても許可したもの以外は全て遮断する為
＃VMの様な内部からのアクセスは許可してもWINDOWSのブラウザ外側からのアクセスは遮断する仕組みになっているからである。
この演習を通してファイアウォールの働きを体感する事ができた。
実際にやってみてセキュリティー面でとても大事な役割を果たしている事を実感した。
